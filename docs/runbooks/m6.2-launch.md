## 0. Preflight

```bash
pnpm deploy:check
```

Perintah ini membaca `.env.production.local` dan gagal jika key wajib masih kosong. Jangan deploy sebelum lulus.

Key yang wajib:

- Database: `DATABASE_URL` (direct owner), `DATABASE_URL_APP` (pooled app), `WORKER_DATABASE_URL` (direct app), `APP_DB_PASSWORD`.
- JWT/secret: `JWT_PRIVATE_KEY`, `JWT_PUBLIC_KEY`, `REFRESH_TOKEN_PEPPER`, `MFA_ENCRYPTION_KEY`, `PII_PEPPER`, `INTERNAL_GATEWAY_SECRET`, `PAYMENT_WEBHOOK_SECRET`, `FILE_SIGNING_SECRET`.
- Upstash: `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`, `QSTASH_TOKEN`, `QSTASH_CURRENT_SIGNING_KEY`, `QSTASH_NEXT_SIGNING_KEY`.
- Cloudinary: `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`.
- Host: `RENDER_API_KEY` (+ `RENDER_OWNER_ID` opsional).
- Web: `WEB_ORIGIN` (https).

Setelah service deploy: `WORKER_URL`, `WORKER_PUBLIC_URL`, `EDGE_URL` (sudah diisi dan diaudit 26 November 2026).

## 2. Deploy service — Render Blueprint (dipilih)

Repo sudah memiliki `render.yaml` untuk empat service: `aletheia-governance`, `aletheia-claims`, `aletheia-payroll`, dan `aletheia-worker` (region Singapore, plan free, Docker).

Langkah di Render Dashboard:

1. **New +** → **Blueprint** → hubungkan repo `ridwanafazn/aletheia` → branch `main`.
2. Render membaca `render.yaml` dan meminta nilai untuk setiap env var `sync: false`. Ambil nilainya dari `.env.production.local`:
   - `DATABASE_URL_APP` (pooled Neon, role `aletheia_app`)
   - `WORKER_DATABASE_URL` (direct Neon, role `aletheia_app`)
   - `JWT_PRIVATE_KEY`, `JWT_PUBLIC_KEY`, `REFRESH_TOKEN_PEPPER`, `MFA_ENCRYPTION_KEY`, `PII_PEPPER`
   - `INTERNAL_GATEWAY_SECRET`, `PAYMENT_WEBHOOK_SECRET`, `FILE_SIGNING_SECRET`
   - `QSTASH_TOKEN`, `QSTASH_CURRENT_SIGNING_KEY`, `QSTASH_NEXT_SIGNING_KEY`
   - `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`
3. Apply Blueprint dan tunggu build/deploy. Docker build memakai `SERVICE_NAME` sebagai build arg dan health check `/healthz`.
4. Catat URL aktual:
   - `https://aletheia-governance.onrender.com`
   - `https://aletheia-claims.onrender.com`
   - `https://aletheia-payroll.onrender.com`
   - `https://aletheia-worker-zjnt.onrender.com` (Render memberi suffix `-zjnt`)
5. Nilai yang sudah diaudit dan harus dipakai:
   - `WORKER_URL` di governance/claims/payroll → `https://aletheia-worker-zjnt.onrender.com`
   - `WORKER_PUBLIC_URL` di worker → URL yang sama
   - `QSTASH_URL` di keempat service → `https://qstash-us-east-1.upstash.io`
   - `GOVERNANCE_URL`, `CLAIMS_URL`, `PAYROLL_URL`, `WORKER_URL` di `.env.production.local` untuk edge
6. Verifikasi health:

```bash
curl -fsS https://<governance>/healthz
curl -fsS https://<claims>/healthz
curl -fsS https://<payroll>/healthz
curl -fsS https://<worker>/healthz
```

Catatan free tier: web service tidur setelah idle. Request pertama bisa cold-start; smoke test menunggu sampai 20 detik per request.

```bash
grep '^JWT_PUBLIC_KEY=' .env.production.local | cut -d= -f2- | \
  pnpm --filter @aletheia/edge-gateway exec wrangler secret put JWT_PUBLIC_KEY --name aletheia-edge
grep '^INTERNAL_GATEWAY_SECRET=' .env.production.local | cut -d= -f2- | \
  pnpm --filter @aletheia/edge-gateway exec wrangler secret put INTERNAL_GATEWAY_SECRET --name aletheia-edge
```

Deploy dengan production vars (ganti URL):

```bash
pnpm --filter @aletheia/edge-gateway exec wrangler deploy \
  --name aletheia-edge \
  --var ENVIRONMENT:production \
  --var GOVERNANCE_URL:https://<governance> \
  --var CLAIMS_URL:https://<claims> \
  --var PAYROLL_URL:https://<payroll> \
  --var WEB_ORIGIN:https://aletheia-web-preview.pages.dev \
  --var COOKIE_CROSS_SITE:true
```

Verifikasi:

```bash
curl -fsS https://aletheia-edge.<subdomain>.workers.dev/healthz
curl -fsS https://aletheia-edge.<subdomain>.workers.dev/readyz
```

Isi `EDGE_URL` di `.env.production.local`.

## 6. Smoke test production

Render free tier tidur saat idle dan cold start bisa lebih dari 2 menit. Hangatkan dulu:

```bash

```

Lalu:

```bash
EDGE_URL="$(grep '^EDGE_URL=' .env.production.local | cut -d= -f2-)" \

```

Uji async QStash/worker:

- Daftar klaim, approval queue, daftar payroll, MIS GraphQL, verifikasi audit chain.
- CSP web.

Tidak ada mutasi finansial pada smoke default. Untuk uji alur penuh, gunakan akun demo dan data sintetis secara manual setelah smoke lulus.

## 7. Rollback drill

### Cloudflare Workers (sudah diuji)

```bash
pnpm --filter @aletheia/edge-gateway exec wrangler deployments list
pnpm --filter @aletheia/edge-gateway exec wrangler rollback <version-id> --message "rollback drill"
curl -fsS https://aletheia-edge.ridwanafzn.workers.dev/healthz
curl -fsS https://aletheia-edge.ridwanafzn.workers.dev/readyz
```

Setelah verifikasi, deploy ulang versi final. Catat kedua version ID.

### Cloudflare Pages (sudah diuji)

```bash
pnpm --filter @aletheia/edge-gateway exec wrangler pages deployment list --project-name aletheia-web-preview
```

Rollback lewat API (token OAuth wrangler) atau dashboard:

```bash
curl -X POST \
  -H "Authorization: Bearer $CLOUDFLARE_OAUTH_TOKEN" \
  "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/pages/projects/aletheia-web-preview/deployments/$DEPLOY_ID/rollback"
```

Verifikasi `canonical_deployment` berubah, web 200, dan header CSP/HSTS tetap ada. Roll forward ke deployment terbaru setelah drill.

### Render (sudah diuji pada `aletheia-claims`; perlu `RENDER_API_KEY`)

```bash
# 1. Cari service dan deploy
curl -H "Authorization: Bearer $RENDER_API_KEY" "https://api.render.com/v1/services?limit=20"
curl -H "Authorization: Bearer $RENDER_API_KEY" "https://api.render.com/v1/services/$SERVICE_ID/deploys?limit=5"

# 2. Rollback ke deploy sebelumnya
curl -X POST -H "Authorization: Bearer $RENDER_API_KEY" -H "content-type: application/json" \
  -d "{\"deployId\":\"$DEPLOY_ID\"}" \
  "https://api.render.com/v1/services/$SERVICE_ID/rollback"

# 3. Roll forward ke commit terbaru
curl -X POST -H "Authorization: Bearer $RENDER_API_KEY" -H "content-type: application/json" \
  -d '{"clearCache":"do_not_clear"}' \
  "https://api.render.com/v1/services/$SERVICE_ID/deploys"
```

Tunggu status `live`, lalu cek `/healthz`, `/readyz`, dan login. Rollback otomatis tidak menonaktifkan autodeploy; freeze deploy selama drill.

### Neon

Gunakan PITR/branch restore hanya jika data rusak; jangan rollback skema yang menghapus kolom.

Setelah semua drill, jalankan `pnpm smoke:production` dan catat hasil di `docs/evidence/m6.2-verification.md`.
