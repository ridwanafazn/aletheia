## 2. TASK-11 — Payslip dan Laporan

### Payslip

* Dibuat hanya untuk batch `APPROVED`, `DISBURSED`, atau `PARTIAL`.
* Dirender dari `payroll.items.calculation_breakdown`, bukan dihitung ulang.
* Memuat identitas tenant dan cabang, periode, nama dan kode personel, PTKP, rekening masked, komponen bruto, potongan karyawan, kontribusi pemberi kerja, net, YTD, policy tag, kode verifikasi, snapshot hash, dan disclaimer.
* Setiap payslip menyimpan `gross_income` dan `net_take_home_pay`. Integration test I-08 memastikan total net payslip sama persis dengan total item.
* Regenerate membuat versi baru dan `supersedes_id`.
* Idempotensi event memakai `source_event_id` dan advisory lock.

### Laporan

| Tipe | Isi | Format |
| --- | --- | --- |
| `PPH21_MONTHLY` | Kode, nama, NIK masked, PTKP, bruto, dasar pajak, PPh 21, net | CSV |
| `PPH21_ANNUAL` | Bruto tahunan, pajak tahunan, selisih, status rekonsiliasi | CSV |
| `BPJS_MONTHLY` | BPJS karyawan dan pemberi kerja per komponen | CSV |
| `BANK_FILE` | Penerima, bank, rekening masked, nominal, referensi | CSV |
| `PAYROLL_VARIANCE` | Net sekarang, net pembanding, delta, alasan | CSV |

Setiap file memiliki header metadata, snapshot hash, dan checksum SHA-256. Status laporan berubah dari `QUEUED` menjadi `READY` setelah worker selesai.

### Rekonsiliasi tahunan

* `POST /api/v1/payroll/reconciliations` menghitung bruto tahunan, PTKP, biaya jabatan, kontribusi yang dapat dikurangkan, PKP, pajak progresif, kredit TER, dan selisih.
* Hasil disimpan sebagai `DRAFT` dengan versi baru.
* `POST /api/v1/payroll/reconciliations/:id/post` memposting oleh Finance dan menegakkan SoD.
* Item bulanan tidak berubah. Integration test membandingkan jumlah dan total net item sebelum dan sesudah posting.

### Unduhan bertanda tangan

* `GET /api/v1/payslips/:id/download` dan `GET /api/v1/reports/:id/download` menghasilkan token HMAC berumur 300 detik.
* Token disajikan melalui `GET /api/v1/payroll-files/:token` tanpa JWT pengguna.
* Audit `PAYSLIP_DOWNLOADED` dan `REPORT_DOWNLOADED` dicatat saat tautan dibuat.
* Berkas disimpan pada `payroll.generated_files` dan disajikan dengan checksum header.

## 3. TASK-12 — Payment Lifecycle

| Kemampuan | Perilaku |
| --- | --- |
| Webhook payroll | `POST /api/v1/payroll/payments/webhook/MOCK`; signature HMAC; event idempoten melalui `payroll.payment_webhook_events` |
| `PAID` | Hanya diterima dari provider saat pencairan atau webhook bertanda tangan |
| `FAILED` | Dari `PENDING` atau `PROCESSING`; item dan batch disinkronkan |
| `REVERSED` | Dari `PAID`; item berubah `REVERSED`, batch menjadi `PARTIAL` atau `FAILED` |
| Reversal | `POST /api/v1/payroll/payments/:id/reverse` dengan alasan minimal 15 karakter; audit |
| Retry | `POST /api/v1/payroll/batches/:id/retry`; hanya batch `FAILED` atau `PARTIAL`; payment baru memakai `attempt_no` berikutnya |
| Idempotensi | Replay request dan webhook mengembalikan hasil tersimpan tanpa duplikasi |

Integration test payroll mencakup reversal, retry attempt kedua, webhook ganda, dan status batch akhir `DISBURSED`.
