## 3. Kontrol Keamanan

- **Policy binding.** Klaim menyimpan `policy_version_id` aktif saat dibuat. Submit dan keputusan membaca versi yang sama, bukan policy terbaru. Policy yang kehilangan kunci wajib ditolak `422`, bukan memakai default 0.
- **PII.** NIK dan rekening tidak pernah disimpan mentah. Hash SHA-256 dengan `PII_PEPPER` dipakai untuk pencocokan lintas domain; UI hanya menerima bentuk masked. Respons dan audit tidak memuat nilai mentah.
- **Idempotency.** Tabel `governance.idempotency_records` menyimpan hash request dan snapshot respons. Replay mengembalikan respons asli dengan `X-Idempotent-Replay: true`; kunci yang dipakai dengan payload berbeda ditolak `409`.
- **SoD.** Maker tidak dapat memutuskan klaimnya sendiri. Pemeriksaan dilakukan sebelum aturan status sehingga menghasilkan `ERR_SOD_VIOLATION`, bukan sekadar RBAC.
- **Concurrency.** Keputusan memakai `SELECT ... FOR UPDATE NOWAIT`. Lima permintaan paralel menghasilkan tepat satu keputusan final.
- **Anti double disbursement.** Klaim dikunci, hanya `APPROVED` yang dapat dicairkan, dan partial unique index menolak payment aktif kedua. Status `PAID` hanya ditulis dari respons provider atau webhook.
- **Routing otorisasi.** Level 1 untuk nominal dalam batas cabang, risiko di bawah threshold, dan tanpa konflik. Level 2 untuk nominal lebih besar, risiko tinggi, atau konflik; hanya Finance Manager yang dapat memutuskan.
- **Review kepatuhan.** Konflik kritis mengubah status ke `COMPLIANCE_REVIEW`. Keputusan transaksi diblokir sampai Compliance Admin mencatat resolusi. Konfirmasi fraud menutup klaim sebagai `REJECTED`.
- **Cloudinary.** Signature memakai SHA-1 params folder dan timestamp. Produksi menolak URL dokumen yang tidak berasal dari cloud name tenant.
- **Webhook.** Body ditandatangani HMAC, nominal dicocokkan, dan status terminal tidak dapat diturunkan kembali. Endpoint menerima identitas `PUBLIC` hanya pada prefix webhook.
- **Audit.** Setiap transisi penting menulis audit di transaksi yang sama melalui `governance.append_audit_log`.

## 4. Bukti Uji

Gate utama:

```text
I-01 maker decide        403 ERR_SOD_VIOLATION
I-02 5 parallel decide   1 x 200, 4 x 409
I-11 forged header       401 ERR_UNAUTHORIZED_ACCESS
I-12 missing policy key  422 ERR_POLICY_RULE_VIOLATION
double disburse          409 ERR_PAYMENT_STATE_CONFLICT
audit verify             valid true checked 35
```

Alur normal:

```text
create    201 DRAFT
submit    200 UNDER_REVIEW risk 15
decide    200 APPROVED
disburse  201 PAID
second    409 ERR_PAYMENT_STATE_CONFLICT
detail    200 DISBURSED, 6 audit entries
```

Alur konflik:

```text
submit              200 COMPLIANCE_REVIEW risk 95
flags               MULTI_CLAIM_SAME_ACCOUNT, SHARED_BANK_ACCOUNT
decide sebelum      409 ERR_COMPLIANCE_REVIEW_PENDING
review              200 ESCALATED, flags FALSE_POSITIVE
branch manager      403 ERR_RBAC_FORBIDDEN
finance manager     200 APPROVED
```

Idempotency:

```text
create replay       200 X-Idempotent-Replay true
payload berbeda     409 ERR_IDEMPOTENCY_CONFLICT
```

## 6. Catatan dan Risiko

1. Evaluasi risiko berjalan sinkron di claims-service sebagai fallback sampai TASK-07. Event `CLAIM_SUBMITTED_EVALUATE` tetap dikirim bila `QSTASH_TOKEN` tersedia.
2. Worker Go belum memiliki handler QStash. Tanpa token, event tidak dikirim dan hanya dicatat di log.
3. Provider `XENDIT` dan `MIDTRANS` belum dikonfigurasi; permintaan provider tersebut menerima `424`.
4. Mock payment memakai `autoComplete` pada demo. Pada lingkungan produksi, status `PAID` harus berasal dari webhook provider nyata.
5. Upload Cloudinary hanya diuji pada tingkat signature; unggahan file nyata dan signed URL belum diuji.
6. Webhook menemukan tenant melalui `provider_reference` yang tidak dapat ditebak. Provider nyata perlu pemetaan akun tenant eksplisit.
7. Reversal payment belum direkonsiliasi ke status klaim; perlu alur manual atau job TASK-15.
8. Rate limit, verifikasi JWT, dan tracing end-to-end menunggu TASK-08.
9. Neon belum diprovision; CI GitHub belum dijalankan.
10. Baris idempotency belum memiliki job pembersihan. Tambahkan retensi 24 jam atau partisi pada TASK-15.
