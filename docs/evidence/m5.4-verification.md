# M5.4 — Runtime RLS & Tenant Binding Verification

* **Tanggal:** 26 November 2026
* **Lingkungan:** Windows 11, Node.js 24, PostgreSQL 16 pada container `aletheia-postgres-test` port `55432`, data sintetis.
* **Status:** Prasyarat runtime M5.4 selesai. Deployment provider eksternal belum dijalankan karena kredensial Cloudflare/Neon/Upstash/Cloudinary/Koyeb-Render belum tersedia.

## 1. Tujuan

Menutup risiko yang tercatat di `docs/15-audit-fix-register.md`: service demo sebelumnya memakai role pemilik database, sehingga RLS tidak aktif pada runtime. M5.4 mewajibkan:

1. Pool service memakai role non-owner `aletheia_app`.
2. Setiap request/transaksi mengikat `app.tenant_id`.
3. Login, refresh, webhook, file download, dan worker tetap berfungsi tanpa membocorkan data lintas tenant.

## 2. Perubahan

| Area | Perubahan |
| --- | --- |
| Database | Migrasi `0008_app_role_login`, `0009_app_role_grants`, `0010_rls_empty_tenant_guard`, `0011_app_role_admin_membership`. Role `aletheia_app` dapat login, seluruh tabel tenant-scoped diberi grant DML, policy memakai `nullif(current_setting('app.tenant_id', true), '')::uuid`, dan role admin dapat `SET ROLE` untuk audit. |
| Pre-auth | Fungsi `SECURITY DEFINER`: `governance.resolve_login_user`, `governance.resolve_refresh_token`, `claims.resolve_disbursement_tenant`, `payroll.resolve_payment_tenant`. |
| Node runtime | `TenantPool` + `AsyncLocalStorage` di `packages/database`. Pool runtime memakai `DATABASE_URL_APP`; migrasi/seed/audit memakai `adminPool` dari `DATABASE_URL`. |
| Middleware | `tenantContext` dipasang setelah `gatewayAuth` di governance, claims, dan payroll. |
| Auth | Login dan refresh melakukan lookup awal melalui fungsi `SECURITY DEFINER`, lalu seluruh transaksi berjalan di `runWithTenant`. |
| Webhook | Claims dan payroll me-resolve tenant dari provider reference sebelum transaksi; file download memakai tenant dari signed token. |
| Worker Go | Context tenant diteruskan ke `pgxpool`; hook `BeforeAcquire` menetapkan `app.tenant_id` dan `AfterRelease` mereset sesi. |
| Dev/CI | `dev-up.sh` mem-provision role dan memakai `DATABASE_URL_APP`; CI database job mem-provision role, memakai app URL, dan menjalankan integration test dengan RLS aktif. |

```json

```

Hasil ini membuktikan worker dapat membaca klaim pada tenant yang benar melalui hook `BeforeAcquire`; tanpa tenant binding, klaim tidak akan ditemukan.

## 4. Perintah reproduksi

```bash
# 1. PostgreSQL lokal
docker start aletheia-postgres-test

# 2. Migrasi, seed, provision role
DATABASE_URL=postgresql://aletheia:aletheia@localhost:55432/aletheia pnpm db:migrate
DATABASE_URL=postgresql://aletheia:aletheia@localhost:55432/aletheia pnpm db:seed
DATABASE_URL=postgresql://aletheia:aletheia@localhost:55432/aletheia \
  APP_DB_PASSWORD=aletheia_app node scripts/provision-app-role.mjs

# 3. Gate
DATABASE_URL=postgresql://aletheia:aletheia@localhost:55432/aletheia pnpm security:db
DATABASE_URL=postgresql://aletheia:aletheia@localhost:55432/aletheia pnpm security:audit

# 4. Integration test dengan RLS
DATABASE_URL=postgresql://aletheia:aletheia@localhost:55432/aletheia \
DATABASE_URL_APP=postgresql://aletheia_app:aletheia_app@localhost:55432/aletheia \
PII_PEPPER=ci-demo-pepper RUN_GOVERNANCE_INTEGRATION=true \
  pnpm --filter @aletheia/governance-service test
```

Ulangi langkah 4 dengan `RUN_CLAIMS_INTEGRATION=true` dan `RUN_PAYROLL_INTEGRATION=true`.
