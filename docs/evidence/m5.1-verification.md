## 2. RLS

`pnpm security:db` memeriksa:

* Setiap tabel dengan kolom `tenant_id` memiliki RLS aktif dan sedikitnya satu policy.
* Tidak ada policy dengan `USING true` atau `WITH CHECK` kosong.
* `governance.tenants` memiliki policy root berbasis `id = app.tenant_id`.
* `aletheia_app` bukan superuser dan tidak memiliki `BYPASSRLS`.
* `aletheia_app` tidak dapat INSERT, UPDATE, atau DELETE `governance.audit_logs`; hanya EXECUTE fungsi append.
* `append_audit_log` adalah SECURITY DEFINER dengan `search_path` eksplisit.
* Tanpa `app.tenant_id`, empat tabel probe mengembalikan 0 baris.
* Dengan tenant SAU, hanya baris SAU terlihat.
* Dengan tenant BPUI, klaim SAU tidak terlihat.

Tabel tenant-scoped yang diaudit: 26 tabel pada schema governance, claims, payroll, dan analytics.

## 4. Header, CSP, dan CORS

Edge menambahkan pada semua respons:

* `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'`
* `X-Content-Type-Options: nosniff`
* `X-Frame-Options: DENY`
* `Referrer-Policy: no-referrer`
* `Permissions-Policy` untuk kamera, mikrofon, geolokasi, dan payment
* `Cross-Origin-Opener-Policy: same-origin`
* `Strict-Transport-Security` saat HTTPS

Web statis menambahkan CSP penuh dengan `script-src 'self'`, `object-src 'none'`, `frame-ancestors 'none'`, HSTS, dan allowlist Cloudinary serta Workers. CORS hanya mengizinkan origin yang dikonfigurasi dan mengirim credential.

**Bukti live 26 November 2026:** `https://aletheia-web-preview.pages.dev` menyajikan `Content-Security-Policy`, `Strict-Transport-Security`, `Cross-Origin-Opener-Policy`, `Permissions-Policy`, `X-Content-Type-Options`, `X-Frame-Options`, dan `Referrer-Policy` setelah deploy ulang. Hostname edge preview `aletheia-edge-preview.ridwanafzn.workers.dev` aktif (200). Edge production baru live di `aletheia-edge.ridwanafzn.workers.dev`; header edge diverifikasi ulang di M6.2.

## 7. Prasyarat Deployment

Service demo masih memakai role pemilik database. RLS dan role `aletheia_app` sudah diverifikasi di database, tetapi service belum mengikat `app.tenant_id` per transaksi pada pool runtime. Compensating control saat ini adalah filter `tenant_id` eksplisit pada seluruh query dan test lintas tenant.

Sebelum production, TASK-18 wajib memakai pool service sebagai role non-owner dan mengikat tenant dari token pada setiap transaksi. Ini dicatat sebagai prasyarat deployment, bukan temuan kode yang belum ditangani.
