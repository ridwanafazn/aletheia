## 3. Kontrol Keamanan

- **Gateway HMAC.** Setiap request non-health wajib membawa `X-User-Id`, `X-User-Role`, `X-Branch-Id`, `X-Tenant-Id`, `X-Gateway-Timestamp`, `X-Request-Method`, `X-Request-Path`, `X-Body-Sha256`, dan `X-Gateway-Signature`. Formula: `HMAC-SHA256(method:path:bodySha256:userId:role:branchId:tenantId:timestamp)`. Timestamp di luar 30 detik ditolak. Method, path, dan body hash dicocokkan ulang.
- **Identitas publik terbatas.** Role `PUBLIC` hanya diterima pada login dan refresh. Endpoint lain menolak identitas publik.
- **JWT.** EdDSA Ed25519, issuer dan audience tetap, TTL akses 15 menit, `jti` unik. Produksi wajib menyediakan pasangan kunci PKCS#8/SPKI.
- **Refresh token.** 48 byte acak, disimpan sebagai SHA-256 dengan pepper, cookie `HttpOnly; SameSite=Strict; Path=/api/v1/auth`. Rotasi mencabut token lama dan menautkan `replaced_by`. Reuse mencabut seluruh family dan menulis audit `SECURITY_EVENT`.
- **MFA.** TOTP dengan secret AES-256-GCM. Recovery code disimpan sebagai hash dan sekali pakai. `MFA_ENFORCED` dapat diaktifkan untuk produksi setelah pengguna privileged melakukan enrollment.
- **Policy dual control.** Pembuat draf tidak boleh menyetujui draf sendiri. Publish hanya untuk draf yang sudah disetujui dan memakai transaksi `FOR UPDATE`; partial unique index menjaga hanya satu kebijakan aktif per tenant dan domain.
- **Audit.** Aplikasi hanya menulis lewat `governance.append_audit_log`. Verify menghitung ulang SHA-256 setiap baris dari kolom kanonik dan `prev_record_hash`, bukan hanya membandingkan rantai. Trigger menolak update dan delete.
- **Tenant isolation.** Semua query menyertakan `tenant_id` dari identitas gateway. RLS tetap aktif sebagai lapisan kedua; probe RLS SAU/BPUI lulus.
- **Redaksi log.** Pino meredaksi authorization, cookie, password, token, secret MFA, NIK, dan rekening bank.

## 4. Bukti Uji HTTP

Urutan policy berhasil:

```text
active   200 v2026.11.01
create   201 DRAFT
approve  200 FINANCE_MANAGER
publish  200 ACTIVE v2026.12.01
verify   200 {"valid":true,"checked":7,"broken_at":null}
```

Rotasi refresh:

```text
login    200
refresh  200
reuse    401 ERR_UNAUTHORIZED_ACCESS
```

Forged signature:

```text
POST /api/v1/auth/login dengan secret salah
401 ERR_UNAUTHORIZED_ACCESS
```

Policy tanpa `sla_target_hours`:

```text
422 ERR_POLICY_RULE_VIOLATION
```

MFA:

```text
enroll  200 secret diterbitkan
verify  200 {"enabled":true}
```

## 6. Catatan dan Risiko

1. Verifikasi memakai PostgreSQL lokal, bukan Neon. Koneksi pooler dan branch Neon belum diuji.
2. `MFA_ENFORCED` masih `false` pada demo. Pengguna yang sudah enrollment tetap selalu diminta kode. Produksi wajib mengaktifkan flag dan mendaftarkan MFA untuk `COMPLIANCE_ADMIN` serta `FINANCE_MANAGER` sebelum flag dinyalakan.
3. Lockout dan rate limit login belum diterapkan. Upstash Redis direncanakan pada TASK-08.
4. Gateway nyata di Cloudflare Workers belum ada; pengujian memakai klien penandatangan Node. Kontrak header sudah final.
5. Kunci JWT, gateway secret, pepper refresh, dan kunci MFA wajib diisi di produksi. Service menolak start tanpa gateway secret dan kunci JWT.
6. Audit verify menghitung ulang hash, tetapi belum menyediakan endpoint ekspor bukti bertanda tangan. Kandidat TASK-15.
7. Endpoint MFA recovery masih memerlukan sesi terautentikasi; alur pemulihan saat login dengan MFA wajib akan disempurnakan bersama UI autentikasi.
