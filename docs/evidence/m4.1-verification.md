## 2. KPI dan Materialized View

* Sumber: `analytics.v_mis_monthly_kpi` dengan filter `tenant_id` dari `app.tenant_id`.
* Kolom: klaim diajukan, klaim disetujui, nominal, approval rate, turnaround, payroll disbursed, PPh 21, budget utilization, dan MoM variance.
* Refresh dilakukan worker dengan `REFRESH MATERIALIZED VIEW CONCURRENTLY`.
* Cache in-process 300 detik per tenant, bulan, dan cabang.
* Header `x-cache` menunjukkan `MISS` atau `HIT`.
* Endpoint `POST /api/v1/analytics/cache/invalidate` membersihkan cache tenant.
* Tren memakai query rentang bulan pada security barrier yang sama.

## 3. What-If

* `POST /api/v1/analytics/what-if` memvalidasi payload, menulis audit `WHAT_IF_REQUESTED`, dan membangun event `WHAT_IF_SIMULATION_RUN`.
* GraphQL mutation `runWhatIfSimulation` memakai jalur yang sama.
* Worker membuka transaksi read-only, menghitung komisi simulasi, menyimpan `analytics.what_if_simulations`, dan menulis audit.
* Item payroll, total item, dan klaim tidak berubah. Test I-05 membandingkan snapshot sebelum dan sesudah.
* Tanpa token QStash, respons `QUEUED` dengan `enqueued=false`. Worker tetap dapat diuji dengan event bertanda tangan.

## 4. GraphQL

Query:

```graphql
query {
  misExecutiveSummary(reportMonth: "2026-11", branchId: "...") {
    branchCode
    totalClaimsSubmitted
    totalPayrollDisbursed
    momVariancePct
  }
  misTrend(reportMonth: "2026-11", months: 6) {
    reportMonth
    totalPayrollDisbursed
  }
}
```

Mutation:

```graphql
mutation {
  runWhatIfSimulation(input: {
    simulationName: "Komisi naik"
    basePolicyVersionId: "..."
    simulatedRulesPayload: { commission_mode: "FLAT_TIER" }
    targetPeriodStart: "2026-11-01"
    targetPeriodEnd: "2026-11-30"
  }) {
    eventId
    status
    enqueued
  }
}
```

Peran yang diizinkan: `MIS_ANALYST` dan `FINANCE_MANAGER`. Query baca juga mengizinkan `COMPLIANCE_ADMIN`.

## 5. Batasan

* Cache disimpan di memori proses governance, bukan Redis. Invalidasi otomatis setelah refresh MV belum terhubung; TTL 300 detik menjadi batas stale.
* What-If creation membutuhkan token QStash untuk diproses otomatis. Demo tanpa token mengembalikan `enqueued=false`.
* UI MIS Dashboard dan What-If Sandbox belum dibuat. Itu TASK-14.
* Cache per proses tidak dibagi antar instance. Produksi multi-instance sebaiknya memakai Upstash Redis.
* Semua perubahan belum di-commit atau di-push.
